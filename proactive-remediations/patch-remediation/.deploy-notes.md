# .deploy-notes.md — PIA/HaloPSA automation requirements

These notes are for the future PIA workflow build-out. They are not Intune-specific.

## HaloPSA trigger

- Ticket source: Datto RMM patch-failure alert.
- Recommended filter:
  - Ticket type = `Datto Alert`
  - Tag = `pia-patch-fix`
  - Status = `New`
- Target queue: Triage / automation-ready queue.

## Custom fields PIA needs from HaloPSA

| Field name | Type | Source | Purpose |
|---|---|---|---|
| `device_hostname` | Text | Datto alert payload | PIA Agent target device |
| `datto_device_uid` | Text | Datto alert payload | Fallback Datto RMM quick job |
| `patch_error_code` | Text | Datto alert payload (optional) | Context for diagnostic |
| `pia_recommended_fix` | Text | PIA writes | Branch selected by diagnostic |
| `pia_last_diagnostic_json` | Multi-line text | PIA writes | Full `CIT-PIA-WUDiag` output |
| `pia_remediation_status` | Text | PIA writes | COMPLETE / FAILED / SCHEDULED |
| `pia_remediation_log` | Multi-line text | PIA writes | Stdout from fix branch |

## PIA workflow structure

1. Trigger: HaloPSA ticket matches filter.
2. Get device from `device_hostname`.
3. Check PIA Agent online status.
   - Offline: route to Datto RMM fallback or escalate.
4. Run `CIT-PIA-WUDiag.ps1` via PIA Agent.
5. Parse `$.RecommendedFix` and branch:
   - `DISKCLEAN` → run `CIT-PIA-WUFix-DiskClean.ps1`
   - `REBOOT` → run `CIT-PIA-WUFix-Reboot.ps1`
   - `WUCOMPONENTS` → run `CIT-PIA-WUFix-Components.ps1`
   - `GENERIC` → run `CIT-PIA-WUFix-Generic.ps1`
6. Wait 60 seconds, then re-run diagnostic.
7. If re-diagnostic shows `$.LowDiskSpace = false`, `$.PendingReboot = false`, and `$.RecommendedFix = GENERIC`:
   - Update HaloPSA ticket with JSON + log.
   - Set status `Resolved`.
8. Else:
   - Update ticket with all attempted steps.
   - Assign to Tier 2 queue, priority Medium.

## Branch-specific behavior

### DISKCLEAN

- Set PIA Agent script timeout to **30 minutes** (DISM can run long).
- Verify output contains `Status=COMPLETE` and free space improved.

### REBOOT

- If output `Action = SCHEDULE_VIA_DATTO`, create a Datto RMM scheduled reboot action and update ticket status to `Scheduled`.
- If output `Action = IMMEDIATE_REBOOT`, wait for agent offline/online transition, then re-run diagnostic.
- Add time-window check: do not force immediate reboot during business hours unless `$.LoggedInUser` is null and the ticket is flagged urgent.

### WUCOMPONENTS

- Set PIA Agent script timeout to **30 minutes**.
- Always recommend reboot afterward. Update `pia_remediation_status` to `COMPLETE_REBOOT_REQUIRED`.

### GENERIC

- Set PIA Agent script timeout to **10 minutes**.
- Wait ~90 seconds after completion before re-running diagnostic so `UsoClient` has time to progress.

## Fallback path

If PIA Agent is offline:

1. Use Datto RMM quick job to run the same PowerShell scripts.
2. Parse stdout for key-value pairs (`Status=...`, `Action=...`, `FreeSpaceAfterGB=...`).
3. Continue the same verification logic.

## KPIs to track

- Tickets auto-resolved.
- Average time-to-resolution.
- Escalation rate by branch.
- PIA Agent offline rate (coverage gap).
